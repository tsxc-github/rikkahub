# DeepSeek 本地 APK 测试报告核对

用户提供报告：`[设备原始日志未公开]`。本次仅核对本地源码和测试覆盖，不改代码、不构建、不安装。

## 确认成立的缺陷

`v2/.../WorkspaceContextProjector.kt:52-56` 对所有非 Markdown 结果，按整个渲染后的 view 是否超过 6144 字节，保存 ref 后改成4096字节预览。

`OpsPage.kt:53-66` 却先给6144字节正文再加文件头、行号和位于末尾的 next cursor。因此即使底层原文预算严格成立，成品页仍可超阈值；投影截断恰好丢掉 cursor。`workspace_result` 也经过该逻辑，恢复出的引用页可能再次变成新 ref。这与报告相符，是本实现的分层契约错误，不是模型调用方法不对。

现有28项测试分别验证 OpsPages 原始body续接和Projector处理人工文本，没有覆盖「页渲染→managedText→Projector→模型可见cursor→下一页」组合。这解释了为何单测通过而装机暴露问题。

## 修复要求（后续已在 a4341901 实现，构建待完成）

实施与37项回归结果见 `V2-PAGING-FIX.md`。以下保留当时的修复契约。

1. 显式区分自分页结果与未分页原始输出。自分页 read/result 页不再接受首屏预览截断；其控制信息和正文属于同一个原子页。不是简单把阈值放大。
2. 保留普通历史的聚合预算/归档，但保证最新恢复页确实进入请求，不能刚恢复就再次归档形成引用循环。
3. 必须补组合回归：20KiB单行、普通多行填满页、ref页，均在投影后提取cursor并续读，证明拼接完整且没有ref套ref。另验证历史预算有压力时仍能恢复所需页。
4. Markdown512KiB例外仍维持，不能借此修复改回小预算。

## 两项显示问题

- grep路径JSON引号来自`OpsQuery.kt:47`，是为了转义冒号/换行等异形文件名而有意生成；不能把去引号当作修复正确性缺陷。可用普通路径直出、特殊路径显式转义/分字段，保留原来的NUL内部帧。
- result 页的 `from line 1` 指向已捕获快照的物理行，而非原文件行号。应区分 `snapshot line` 与 `source line`，不虚构原文件映射；原页若自带源行号则保留。
