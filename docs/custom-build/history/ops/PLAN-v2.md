# RikkaHub ops v2：围绕累计请求上下文重写

> 2026-11-05，待用户批准的设计稿。**本轮只写方案，不改源码、不构建、不安装、不改主机/CT 配置。**
> 依据：当前上游基线 `base/v3.1.1 = 903e058b`；现有 ops HEAD `641d6bf1`；审查报告 `REVIEW-2026-11-05.md`。后续若上游版本变化，须先重新核对接入点。

## 已批准的实施补充（2026-11-05）

用户批准写代码，并要求长 Markdown 文档可全量输出或给很大预算。实施规则：`.md`/`.markdown`（忽略大小写）在未传 offset/limit/cursor 时默认 **512 KiB 原文预算**；超过才给可恢复分页。Markdown 正文**不进入普通 workspace 的 32 KiB 历史折叠预算**，在实际上下文里保留全文直到上游正常压缩/裁剪，完全重复页仍可安全去重。显式 offset/limit/cursor 表示主动选窗口，不强制整读。通用输出包装器不得再次把 Markdown 转为小预览。此规则优先于下文旧默认值，必须有独立回归测试，不能“读全后在请求投影中又截掉”。

## 1. 重新定义目标

不是「每个工具输出砍短一点」，而是：

**在完成同样任务、结论可核查、需要时能取回证据的前提下，减少整个任务累计发送的输入上下文，兼顾请求轮次与前缀缓存。**

分开测量：

1. 每次请求的工具正文、工具 schema、其他消息的字节数。
2. 全任务这些量的累计值，以及输入/缓存 token（提供方有 usage 才报告真实值）。
3. LLM 请求轮次、读取/搜索/翻页次数、任务是否完成且证据是否正确。
4. 不把 bytes/4 当真实 token 数，不把缓存命中当作上下文消失。

举例：连续读 20 个各 6 KiB 的窗口，仅做单次限额，最后一次请求仍可能携带约 120 KiB 工具正文。v2 既限制单次输出，也把实际请求中托管的工作区正文控制在约 32 KiB；旧结果留可取回的引用，而非一直全文随请求发送。

### 更正旧文中的一个前提

`AgentLoop.kt:49-63,159-170` 是一次模型响应中的多个工具逐个执行完，再调用模型。**串行执行多个工具 ≠ 每个工具都单独请求一次 LLM。** 不再以这个错误前提证明并行或新增批处理工具能省输入上下文。本期不改调度循环。

## 2. 范围与非目标

### 本期完整重写

- 所有旧 `Ops*.kt` 实现及其接入钩子，不 cherry-pick 原 10 个 ops 提交。
- read/grep/glob/result 四个原语的预算、续读和状态协议。
- 工作区工具输出的引用存储。
- **在最终发给模型的消息副本上**做预算投影、确定性历史折叠及安全去重。
- 相应 JVM 测试、后端契约测试、请求快照测试、实机 smoke 与测量。

### 不做

- 不额外调用 LLM 总结工具结果，不为省 token 再花一次生成。
- 不改用户正文、助手结论、reasoning/signature、图片、供应商原生 server tools。
- 不统一改写网页搜索结果 JSON、MCP 返回结构。先覆盖占用大头的 workspace；其他工具保留上游行为。
- 不动态披露工具、不造通用 PTC/batch DSL、不做工具并行、不加中间件/服务/数据库。
- 不把 shell 上游已经截掉的部分伪称为已保存全文。上游 shell 输出采集上限本期不扩容。

## 3. 总体架构：原始结果与模型视图分开

```text
工作区执行
  → 有界取数 + 类型化结果/完成状态
  → UI/历史保留原有结果（或明确的结果引用）
  → 本地不可变结果存储（需要时保存）

每次构建模型请求
  → 上游 limitContext + 输入转换
  → WorkspaceContextProjector（仅处理消息副本）
      1. 验证/建立可取回引用
      2. 分配本次正文预算，确定哪些结果保留正文
      3. 在这些实际保留的正文中选择去重锚点
      4. 其余结果替换成短回执
      5. 去掉本地 ops metadata，保持其他 metadata
  → Provider 编码 / 请求
```

**关键区别**：历史库是资料库，不等于模型上下文。UI 里是否还在、数据库里是否存在，不能成为省略正文的充分条件。

本地信息使用已有 `UIMessagePart.Text.metadata` 的命名空间字段携带，如 `ops_v2`；由应用包装器创建，不从工具输出正文猜测。保留 provider 的原 metadata，不覆盖 thinking/signature 等字段；发送副本中移除本地字段。此方案无需改变消息表结构，但需要序列化/Provider 回归测试。

## 4. 初始预算（设计起点，不冒充 token 基准）

| 内容 | 默认预算 | 说明 |
|---|---:|---|
| read/result 的一次正文 | 6 KiB UTF-8 | 结合行数上限，先达到者停；允许精确续接 |
| grep 一次正文 | 4 KiB / 最多 40 条命中 | 不全量计数，不隐藏每文件上限 |
| glob 一次正文 | 3 KiB / 最多 80 条路径 | 排序稳定；是否还有更多需有证据 |
| shell 模型首屏 | 4 KiB | 按已知类型处理 stdout/stderr/exitCode/truncated |
| workspace 正文在每次请求中的合计 | 32 KiB | 仅约束托管工具正文，不包括 schema、参数、必需状态/短回执和非 workspace 内容 |
| 折叠后的回执 | 目标约 120–240 字节 | ref + 结果类型/来源 + 状态；错误时保留简短原因 |
| 未识别工具/非 workspace | 保持上游 | 不把所有工具一刀切成 ref |

- 单次页可以在实现测试中微调；默认不能再保留「不带 offset 就整文件读完」这条旁路。
- 行号/路径/状态也要计入实际序列化字节报告，不能只统计正文后宣称请求总量被硬限住。
- 32 KiB 不是整个请求的硬上限：大量工具参数、错误回执、用户长文本、图片和 schema 都另计。极端消息数仍交由上游上下文裁剪/压缩处理，不能删除 tool call/result 配对来硬凑上限。
- 一次请求中的新工具组若超过正文预算，至少让最近结果有可用正文，其余结果同样可折叠成有效 ref，不存在「当前轮无限豁免」。

## 5. 文件读取：默认有界，不先扫描整文件

保留 `workspace_read_file(path, offset?, limit?)`，增加可选不透明 `cursor`，旧 offset/limit 继续可用。

### 默认行为

- 小文件：一页返回完。
- 大文件：只取当前窗口，遇预算或行数上限停止；多读必要的探测单元判断是否到 EOF。
- 不为显示总行数额外跑全文件 `awk END` / `wc`；能直接 stat 的大小可显示，总行数未知就不显示。
- 不把整文件先读进应用内存后再分页；不依赖远端 Python 或常驻服务。
- 本地 PRoot/SSH 采用相同的查询契约，使用受控 shell/流式工具。实现阶段先锁定实际可用的基础命令，再用后端契约测试验证；不靠未探测的命令选项兜底。

### 长行与续接

不能再「截掉前 400 字符以后的内容，下一页跳到下一行」。

- cursor 能表达同一行的继续位置；不得切坏 UTF-8 字符。
- 页面显示原行号及 continuation 标识，不把分段冒充原文件换行。
- `next` 指向第一个**尚未返回**的位置，保证不漏、不重。
- offset/limit 是按原文件行计数；要精确续接长行使用返回 cursor，不能自己猜 offset+limit。
- cursor 与 path/版本及查询参数绑定；混用 cursor 与冲突参数返回参数错误。

### 文件变化语义

文件是 live source，不承诺多页读取等于同一时刻全文件快照。cursor 保存观察到的源信息，读前后核对；检测到变化回 `source_changed`，不悄悄拼接。mtime/size/inode 只是变化检测，不冒充完整内容哈希；需要强一致全文件快照时必须显式复制/冻结，默认不为此扫描并复制巨型日志。

每个已返回的页面可存为不可变结果；历史引用重新读取的是当时的页面，不会重新执行一个可能已变的文件查询。

图片分支及其审批语义保持上游，不进入文本预算逻辑。

## 6. 结果存储：保存真实收到的内容，不猜 JSON 信封

### 存什么

- 原始 UTF-8 文本/已知的分段结果 + 小型版本化 manifest。
- manifest 包括来源、哈希、编码、观测范围、完成状态、创建时间、会话/工作区归属等。
- shell 用明确的类型适配器保存 stdout/stderr/exitCode/timedOut/truncated；普通 JSON 文档不按字段名猜测展开。
- 搜索保存的只是已采集结果，不伪称整个目录搜索快照。
- 同内容可在同一作用域复用存储，但磁盘去重与模型正文去重是两件事。

### 怎么读

保留 `workspace_result(ref, offset?, limit?)`，增加可选 cursor。

- 旧行号页兼容短行使用；一旦行内分段，返回明确 cursor。
- 按文件流/范围读，不每页 readText + split 全文件。
- 不会给 result 再套一层转引用，避免 ref 套 ref。
- 历史 v1 的 32 hex ref 提供只读兼容路径；不重写旧文件，不把旧 store 与新 store 混着清理。

### 生命周期

- 新存储隔离在版本目录，manifest 与数据用临时文件 + 原子发布；并发写入/淘汰由应用内 Mutex 保护，不新增守护进程。
- 上限先沿用约 200 MiB / 200 项，最旧先淘汰；本次新写入及正在被请求使用的结果受短期保护。
- 单个结果装不下或磁盘失败时明确报告，不返回一个刚写就被删除的 ref。
- 结果不是永久档案。已淘汰返回 `expired`；有 UI/数据库原始正文时允许重新建立引用，否则不能伪造全文。
- **投影前必须确认 ref 存在或可重建**。存储失败且无有效恢复路径时，不做归档折叠，保留原始已采集结果并显示降级原因；必要时允许本次请求超出正文目标预算，正确性优先。此时明确标记预算未达成，不能为了凑 32 KiB 而把唯一原文丢掉或改成无效引用。
- ref 不是恢复任意路径的能力：严格 ID 校验、作用域检查，不拼接外来路径。

## 7. 搜索：以少量可信命中替代大量可疑命中

保留 `workspace_grep` / `workspace_glob` 名称；精简描述，不新增工具。默认鼓励先列路径再读窗口。

### grep

- 增加低成本 `filesOnly` 模式：定位相关文件时只返路径，不把每个命中行都带上。
- 需要上下文时再返回 path:line:text；同一文件路径可分组显示，避免重复长前缀。
- 去掉隐藏的每文件 8 条上限。若将来提供 perFile，必须成为显式参数/状态。
- 取 N+1 或由可验证的提前终止标记判断 `has_more`；不声称知道全量总命中数。
- 状态区分：`complete`、`limited`、`source_truncated`、`partial_error`、`timeout`、`error`。
- 只有真正完成搜索且零命中、零错误，才能说 `no match`。
- stderr/权限失败必须影响完整性状态；不能把错误文件内容当正常命中。
- 搜索按明确稳定顺序输出；结果超限优先提示收窄查询，不默认落盘所有海量命中。续查可以重新搜索更窄的范围，而非制造一个假的全量结果 ref。

### glob 一种语义，两种后端同一结果

为避免再造一套完整 gitignore 引擎，第一版只承诺**文件名 glob 子集**：`*`、`?`、`[abc]`、`[!abc]`。作用于 basename；含 `/`、`**`、`!前缀`、花括号扩展等明确报 unsupported，不静默降级。

- 目录范围用 path 参数表达；更复杂筛选仍可通过 shell 执行。
- rg 分支与 fallback 都从同一份文件选择语义开始，再做命中预算；不能 head 后才按 glob 筛选。
- rg 只承担已选文件的内容搜索；安全处理空格、冒号、换行、以 `-` 起始的文件名，不使用路径冒号分割来恢复结构化字段。
- 根目录 `/` 必须有效；权限错误不能固定 rc=0。
- 若没有满足契约的检索命令，应明确不可用，不能把功能不等价当作 fallback 成功。

**取舍**：功能语法窄一点，但结果一致可测。默认快路径仍为 `*.kt` / `*.md` 等常见定位，不用为复杂语法付出长期维护成本。

## 8. 真正省历史上下文：在请求投影阶段处理

接入点是 `ChatRequestFactory.buildStep()` 中上游 `limitContext` 和所有 input transformers 完成后、返回 `StepRequest` 前。此路径也用于压缩请求，不能只覆盖普通生成。

### 8.1 正文预算

- 只操作实际参与本次请求的消息副本，不查数据库全历史来决定可见性。
- 优先保留较近、可直接帮助下一步工作的结果；旧结果超预算后变成来源/状态/ref 短回执。
- 不改 toolName、toolCallId、参数、审批、成功/失败，不删除 tool/result 配对；非文本部分保持原样。
- 分配以正文为单位，不让一个长 shell 输出顶掉所有近期短证据；最近请求的 result 页优先，防止刚恢复的内容下一刻又被折掉。
- 本期不做自动语义摘要，折叠不声称保留了证据结论；需要正文时用 ref 取回。

### 8.2 安全去重

- 在**已完成裁剪并确定会保留正文的那份请求**中，选择相同来源/范围/输出版本/实际字节哈希的一个锚点。
- 其他完全相同的正文可以只回一行「同本请求中 toolCall X；备用 ref Y」。
- 锚点不能在随后预算步骤中再被折叠：先定保留集合，再做去重，最后校验全部指向关系。
- 不对“模型大概看过”“DB 里还在”“mtime 一样”做正文省略。
- 无锚点但有有效 ref 的情况叫**归档折叠**，不是去重；回执必须要求按需恢复，而非宣称正文已在上下文。
- 每次请求重算，压缩/分支/删除/重试后自然使用新的最终消息集合。

### 8.3 前缀缓存代价

投影会改变请求历史字节，不是免费午餐。

- 不每增加一页就移动整个历史窗口；采用确定性分档/滞回边界，借鉴上游 limitContext 的阶梯策略。
- 以明确的工具结果顺序/轮次边界确定折叠批次，无随机摘要、无时间戳噪声；同一请求重复构建得到完全一致的视图。
- **不随新重复读把锚点从旧结果搬到新结果**：在有效且保留的结果中固定选择最早锚点，直到它所在批次真的折叠。
- 默认先按预算分配，在达到触发阈值时一次折叠一批，预留增长空间。32 KiB 是目标正文硬限；滞回只决定折叠批次，不允许越过目标后无限保留。
- 如果对 usage 的实测显示失去缓存的代价大于正文缩短收益，回退为“只在下一用户轮次边界折叠历史 + 本轮执行单次预算”；不是拿静态字符数掩盖付费输入增加。
- 存根数量仍会增长，因此不宣称整个会话永远常数空间；上游上下文压缩仍负责长期对话。

## 9. UI、历史与协议兼容

- 数据库里已有用户/助手消息不批量改写，不迁移消息表。
- 新输出有受控本地 metadata；本次发送只替换副本，用户回看不因上下文节省而失去原始输出。
- 旧 workspace 历史可按 toolName 识别为候选，但没有可信来源信息时不做“同文件未变”去重；可按原文本保存新 ref 后归档。
- 老版去重存根已经缺失正文的，不可能凭空恢复；需要显式读取源文件/已有引用。不伪造迁移成功。
- tool schema 保持现有名字，只增加必要可选字段，避免旧提示词/历史调用全部失效；不为了少几个 schema 引入巨大的 union DSL。
- workspace 工具只在对应工作区就绪时提供；result 在本会话有引用可用或工作区可用时提供。后续根据 schema 字节与缓存实测决定进一步缩减，不先做动态披露。
- debug/release 包名、versionName 与上游同号、官方更新提醒策略沿用已定规则；不借重写改变这些决定。

## 10. 文件/接入点与分层

候选文件（实施时按真实源码定最终名字）：

- `WorkspacePageReader`：流式取页、UTF-8/长行/cursor/来源变化。
- `WorkspaceQueryTools`：read/grep/glob/result 的薄适配与简短 schema。
- `ToolResultStore`：不可变数据、manifest、分页、保护/淘汰。
- `WorkspaceOutputAdapter`：已知工具类型 → 原始内容与模型视图信息，不猜 JSON。
- `WorkspaceContextProjector`：最终请求的预算分配、历史折叠、可见集合去重。
- `OpsBudget`：少量集中常量；无额外设置页。

主要上游钩子：`WorkspaceTools`、`ChatToolFactory`、`ChatRequestFactory.buildStep`；必要的 workspace 读取契约只在确认现有接口不足时扩展。不为了“每处不超过10行”把正确的状态流藏在字符串里，但尽量限制接入点，不改 AgentLoop/Provider 的核心调度。

需要验证但不能凭设计宣称已解决的部分：便携流式页读取脚本/帧协议、不同 Provider 对本地 metadata 的处理、输入转换后投影会否影响供应商消息配对，以及上游压缩请求对 ref 归档历史的可读性。

## 11. 回归与验收门槛

### 正确性：先测，再实现/替换

1. 普通/空/无末尾换行/CRLF/多字节 UTF-8/超长行/最后一行。
2. 连续 cursor 拼接结果与目标原文逐字节一致；无漏字符、无重复、无伪造原行号。
3. >8 MiB 文件能读取小窗口，默认读取不扫描总行数、不整文件加载。
4. 同内容跨轮、同轮；压缩检查点前的重复；contextMessageLimit 裁剪；分支切换/删除；正文去重锚点始终在最终请求里。
5. 归档后的 ref 能还原原页；来源文件修改不影响已保存原页；live source 变化给明确状态。
6. 容量/数量/单项超限、磁盘失败、取消、重启恢复、并发清理，新 ref 不会成功返回后立即失效。
7. grep 单文件 >8 命中、N+1、字节限额、0命中、超时、权限失败、根目录；rg/fallback 同语义。
8. 文件名含空格、冒号、引号、换行、前导 `-`；不从不可靠文本分隔符猜文件字段。
9. shell 超上游采集上限：状态明确为 source_truncated；ref 不声称能恢复没采到的输出。
10. 图片、search_web 引用、MCP JSON、reasoning/signature、审批拒绝/待批、写文件/编辑、重试和压缩不受破坏。
11. 原始历史不变、投影幂等/确定；OpenAI Chat/Responses、Anthropic、Gemini 等实际使用的 Provider 编码快照配对合法。
12. 回执数量/大参数导致预算无法代表整请求时，测量诚实，无无限“读 ref → 又归档 → 再读 ref”的循环。

### 性能/收益

固定脚本化任务对比：上游、现有 ops、v2。样本至少包括：定位符号再读多个文件；大日志定位；跨轮重复读；连续多页；压缩后再读；低输出普通聊天。

- 先用可重复的脚本/请求快照比较工具正文、schema、请求轮次与任务证据，不靠 LLM 随机行为得出百分比。
- 再少量实际模型任务测 usage；固定模型、相同任务/初始历史，记录缓存 token，不把单样本当统计结论。
- 硬门槛：可恢复性/状态测试全过，托管正文满足预算，低输出任务不明显增加 LLM 轮次。
- 大工具输出任务的目标：明显降低累计正文、且不因过细分页把节省全部换成额外请求。**具体降幅待测，暂不承诺 50%/80%。**

## 12. 实施/回退步骤（获准后）

1. 保留旧 ops 分支、补丁、APK；为当前 HEAD 建明确归档锚点。从同一上游基线新建 `ops-v2`，不是 reset/强推现有 ops。
2. 先建立测试夹具与性能基线，不立即编全 APK。
3. 新实现 read/result/store，先通过完整性与后端契约测试。
4. 新实现查询原语及状态契约，验证 rg/fallback 一致。
5. 新实现最终请求投影，默认开启正文预算/历史折叠；安全去重必须在最终请求快照测试过后才启用。
6. 独立提交 build 配置与工具实现；构建参数不混进功能补丁。
7. 一次后台 debug 构建；用户下一次查询时单次查日志，不 sleep、不轮询。先并存包验证，再经用户确认安装 release。
8. 验收后导出干净 patch series，更新唯一 README 索引、旧方案标注 superseded，但保留审查与旧补丁便于回退。

拟分 5 个可审提交：测试与基线 / page+store / 查询工具 / 请求投影与安全去重 / 构建交付与文档。

不改变 PVE/CT 的内存、swap、核数、磁盘、网络，不安装新服务。发现必要的环境改动时另外请示，不能把本方案获准当作机器配置改动授权。

## 13. 需要用户确认的总体取向

推荐按本文实施：**默认有界读取 + 精确可恢复引用 + 最终请求正文预算/历史折叠；去重只在实际请求中做。**

三个明确代价：

1. 大文件不再默认整读；复杂 glob 第一版不支持，需缩小目录/使用 shell。
2. 已折叠旧证据可能多一次按需恢复请求，不能保证始终零额外往返。
3. 投影改变历史前缀，必须实测缓存后的净收益；必要时降低折叠频率。

用户批准的是这个设计方向。任何为了凑字符指标而丢证据、假装结果完整、或隐藏新增请求轮次的实现，都不算完成目标。
